## Why

自動生成支撐點後對物件執行**鏡像**或**非 Z 軸旋轉**，再次進入支撐模式時，整排支撐點的位置被拉長／位移，明顯不再貼合模型表面。對物件執行 **Z 軸旋轉**則無此問題。

這個「只有非 Z 軸變換才出事」的分界，與引擎層的設計恰好吻合。`SLAPrint::sla_trafo()`（`SLAPrint.cpp:234`）的註解寫得很明白：

> `// Transformation without rotation around Z and without a shift by X and Y.`

它**刻意排除 Z 旋轉與 XY 平移**（兩者不改變列印方向），但包含 X/Y 旋轉、`relative_correction()` 縮放、instance 縮放、鏡像，以及左手座標時額外的 `Scaling(-1,1,1)`。而 `SLAPrint::apply()`（`SLAPrint.cpp:562`）對此有正確的失效判定：

```cpp
bool sla_trafo_differs = ... || !sla_trafo(model_object).isApprox(sla_trafo(model_object_new))
                             || is_left_handed 改變;
if (model_parts_differ || sla_trafo_differs) {
    update_apply_status(it_print_object_status->print_object->invalidate_all_steps());
    ...
}
```

**所以缺口不在引擎層，而在 gizmo 前端的支撐點快取沒有跟著 `sla_trafo` 失效。**

已確認的一個具體缺口：`GLGizmoSlaSupports::data_changed()`（`:429`）只在**物件 ID 改變**時才 `reload_cache()`：

```cpp
if (m_state == On && mo && mo->id() != m_old_mo_id) {
    disable_editing_mode();
    reload_cache();
    ...
}
```

鏡像／旋轉不會改變 `mo->id()`，因此只要 gizmo 在變換發生時仍開著，`m_normal_cache` 就原封不動地留著變換前的點，再被新的 instance transform 畫出來。

另有一個尚未證實的候選機制：`get_data_from_backend()` 以 `po->trafo().inverse()` 把 backend 點換算回 object space，而該 trafo 排除 Z 旋轉與 XY 平移、卻包含 corr 縮放與鏡像；渲染路徑則使用完整的 instance transform。這條來回換算若有不對稱（特別是左手座標時 `sla_trafo` 多乘一次 `Scaling(-1,1,1)`），就會產生只在非 Z 軸變換後才顯現的位移。

### 已排除的成因

本缺陷於 `perf-sla-support-points-preview-render` 的驗收（任務 7.7）期間發現，經比對確認與該 change 無關：

- 症狀是**整排點一起**位移，而非單顆錐體變形。
- 該 change 的錨點運算式 `instance_scaling_matrix * support_point.pos` 與其修改前的 `head.pos = instance_scaling_matrix * support_point.pos` **逐字相同**，只有「烘進頂點 vs. 交給 model matrix」的差異，代數上恆等，不可能改變點雲分布。
- 該 change 從未寫入 `m_normal_cache` 的內容。

## What Changes

- **先診斷後修正**：本 change 的第一階段是把「拉長」的實際機制定位到單一原因（前端快取未失效 / trafo 來回換算不對稱 / 兩者疊加），再據以修正。診斷步驟與判別方式列於 design 與 tasks。
- 讓 gizmo 前端的支撐點快取在 `sla_trafo` 改變時失效，與 `SLAPrint::apply()` 的既有判定對齊——而非新發明一套清除規則。
- 依 `mo->sla_points_status` 分流處理：
  - `AutoGenerated` / `Generating`：失效並重新生成（這些點是依列印方向算出來的，換方向後語意上已無效）。
  - `UserModified`：**保留**手動點，不清除；依需要提示使用者重新檢視。
- per-point 幾何參數（頭部直徑、penetration、contact 球半徑等）**不清除**——它們與列印方向無關，鏡像後仍然有效。

### Non-goals

- **不「有編輯行為就清除所有支撐與其參數」**。手動點存在 object space、是使用者刻意逐顆放置的，一律清除會嚴重損害可用性；per-point 參數與方向無關，清除只會讓使用者白白重設。
- 不改變 `SLAPrint::sla_trafo()` 的定義或 `SLAPrint::apply()` 的失效判定——引擎層已經是對的。
- 不改變 Z 軸旋轉與 XY 平移不觸發失效的既有行為。
- 不改變 Points preview 的渲染路徑、快取或效能特性（`perf-sla-support-points-preview-render` 建立的機制維持不變）。
- 不處理支撐點 undo/redo 資料問題（→ `fix-sla-support-points-undo-snapshot`）。

## Capabilities

### New Capabilities

- `sla-support-points-trafo-invalidation`：物件變換改變 `sla_trafo` 時，SLA Support gizmo 前端支撐點快取（`m_normal_cache` 及其衍生狀態）的失效規則。涵蓋「哪些變換觸發失效」、「`AutoGenerated` 與 `UserModified` 的分流」、「per-point 參數不得被清除」，以及「preview 顯示的點必須與當前 instance transform 一致」的不變式。
