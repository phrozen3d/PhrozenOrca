## 1. 診斷（必須先完成才進入修正）

見 design.md D1。三個候選機制的修法不同，同時套用會讓驗證失去意義。

- [ ] 1.1 建立可重現案例（auto generate 一次 → 沿 X 軸鏡像 → 進入支撐模式），截圖並記錄四項：
      **(a)** 是整片點雲被「放大」（點與點的間距變大），還是整片「平移／旋轉」到錯的位置？
      **(b)** 沿哪個軸？單軸還是多軸？
      **(c)** 目測倍率大約多少？與物件的 scale 值是否相關？
      **(d)** 點雲的形狀還認得出是模型底面的輪廓嗎？
      → **(a) 是候選 A 與 B 的主要分水嶺**：等比放大指向 B（縮放因子沒抵消）；形狀正確但貼在變換前的位置指向 A
- [ ] 1.2 同樣流程改用繞 X 軸旋轉 45 度，比對症狀是否一致
- [ ] 1.3 對照組：改用繞 Z 軸旋轉 90 度與 XY 平移，確認確實無症狀（驗證 `sla_trafo` 排除規則的分界）
- [ ] 1.4 **候選 A 判別**：在變換前後印出 `m_normal_cache.size()` 與前三顆點的 `pos`。若變換後與變換前逐位元相同 → 快取根本沒重載
- [ ] 1.5 **候選 B 判別**：取一顆點，手算 `sla_trafo⁻¹ · backend_pos`，再套用渲染端的 `instance_matrix_no_scale · (S · pos)`，與模型表面實際座標比對。若偏差恰為某軸的縮放或反射因子 → 換算不對稱
- [ ] 1.6 特別檢查左手座標路徑：`sla_trafo()`（`SLAPrint.cpp:265-266`）在 `is_left_handed()` 時額外左乘 `Scaling(-1,1,1)`，確認 `get_data_from_backend()` 的 `po->trafo().inverse()` 與渲染端對鏡像的處理是否對稱
- [ ] 1.7 檢查 `relative_correction()`（`sla_trafo()` 的 `trafo.scale(corr)`）在本機 printer profile 下是否為 (1,1,1)。若非，確認渲染端有無對應的還原
- [ ] 1.8 確認 `SLAPrint::apply()`（`:562-572`）在該情境下確實走進 `invalidate_all_steps()` 分支，且 `has_backend_supports()` 隨之回傳 false
- [ ] 1.9 **gizmo 開著 vs 關著**：同樣的變換做兩次——(a) gizmo 開著時直接鏡像；(b) 關掉 gizmo 再鏡像後重開。症狀是否相同？程度有無差別？
      → 只有 (a) 有問題 → 純候選 A（`data_changed()` 的 ID 判定）；兩者皆有 → 含候選 B
      （注意：第 6 節的 6.3 / 6.4 是**驗收**用途——確認修好後兩種情境都正確；此處是**診斷**用途——用兩者的差異收斂根因）
- [ ] 1.10 **會不會自己恢復**：變換後停在支撐模式，等背景重算跑完（10~30 秒）且不做任何操作，點會不會自己跳回正確位置？
       → 會 → 時序問題（讀到尚未更新的中間狀態）；不會 → 換算或快取的持久性錯誤
- [ ] 1.11 **先鏡像再生成**：先把物件鏡像，之後才 auto generate，這樣產生的點正常嗎？
       → 正常 → 問題只在「既有點 + 後續變換」；也不正常 → 換算本身就有錯，範圍比預期大
- [ ] 1.12 **縮放是否也觸發**：分別測均勻縮放 1.5× 與非均勻縮放 (2,1,1)，是否也出現同樣症狀？
       `sla_trafo()` 含 `trafo.scale(model_instance.get_scaling_factor())`，理論上會觸發；1.2 / 1.3 目前只涵蓋旋轉與平移。若縮放也會，spec 的 scenario 需補上
- [ ] 1.13 **產出結論**：症狀屬候選 A、B 或 C（A+B）。未得出結論前不進入第 2 節

## 6. 驗收

- [ ] 6.1 auto generate → 沿 X 軸鏡像 → 進支撐模式：支撐點貼合鏡像後表面，無整排位移或間距拉開
- [ ] 6.2 auto generate → 繞 X / Y 軸旋轉 → 進支撐模式：同上
- [ ] 6.3 **gizmo 開啟中執行變換**：不關閉 gizmo 直接鏡像／旋轉，preview 立即反映新座標（診斷階段的 1.9 用兩者差異收斂根因；此處是確認修好後兩種情境都正確）
- [ ] 6.4 **gizmo 關閉中執行變換**：關閉後鏡像／旋轉再重開，preview 正確
- [ ] 6.5 **縮放情境**：若 1.12 確認縮放也會觸發，均勻與非均勻縮放後 preview 亦須正確
- [ ] 6.5 **Z 旋轉不失效**：繞 Z 軸旋轉 90 度，支撐點數量與內容不變、不觸發重新生成、隨物件轉動且持續貼合
- [ ] 6.6 **XY 平移不失效**：移動物件位置，支撐點數量與內容不變、不觸發重新生成
- [ ] 6.7 **手動點不被刪除**：`UserModified` 狀態下鏡像與非 Z 旋轉後，手動點仍存在且數量不變
- [ ] 6.8 **per-point 參數不變**：帶不同頭部直徑的手動點，鏡像後各自參數與變換前完全相同
- [ ] 6.9 連續執行 Z 旋轉 → 非 Z 旋轉 → 鏡像，每一步後 preview 皆正確，無需重開 gizmo 才修正的中間狀態
- [ ] 6.10 法線快取隨點集失效：變換後 cone 朝向依新表面重算，無舊法線殘留
- [ ] 6.11 幾何快取未被誤清：變換後穩態每幀 `GLModel::init_from()` 呼叫次數仍為 0
- [ ] 6.12 picking 與顯示一致：變換後 hover / click 的命中位置與可見錐體相符
- [ ] 6.13 切片輸出與變換後的 preview 一致
